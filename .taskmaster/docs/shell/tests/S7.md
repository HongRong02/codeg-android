## A1 服务器更新与网页入口补充

通过测试服务器网页临时按钮执行 `CodegShellUpdate.check()`；版本显示执行 `CodegShellUpdate.versionName()`。协调方预置可切换的 latest/APK 响应，并观察服务端或代理请求日志。

| 编号 | 优先级 P0/P1 | 步骤 | 预期 |
|---|---|---|---|
| A1-01 | P0 | 服务器发布高于当前 version_code 的 APK 和正确 sha256；启动 release，点下载并安装 | 优先请求服务器 latest/APK；不请求 GitHub；显示版本和说明，校验通过后启动安装器 |
| A1-02 | P0 | latest 返回 404，GitHub 准备更高 build-N；点击网页检查更新 | 回退 GitHub，显示其更新说明并可下载安装；存在 APK.sha256 时校验 |
| A1-03 | P0 | latest 返回新版但 sha256 为 64 个 0；下载并安装 | 显示下载或校验失败；缓存 APK/part 删除，不启动安装器；修正后可重试 |
| A1-04 | P0 | latest 返回与当前相同或更小的 version_code；点击检查更新 | 显示“已是最新版本（当前版本）”；不请求 GitHub；versionName() 等于当前安装版本 |
| A1-05 | P0 | latest 返回新版；先点稍后，再于 6 小时内点击网页检查更新 | 手动检查忽略 6 小时节流和同版 24 小时静默，重新显示更新对话框 |
| A1-06 | P0 | 导航至外部 origin；尝试调用网页桥和未注入包装的原始 CodegShellUpdate；从当前网页嵌入外部 iframe 并尝试调用 | 外部文档无可用网页入口；原始接口缺少随机凭据不响应；不发起检查、不显示版本或更新提示 |
| A1-07 | P0 | 安装 debug；启动和后台恢复；随后从当前服务器网页点击检查更新，下载并授权安装 | 自动检查关闭；手动可用；新版对话框注明调试版和正式版为另一应用；授权返回后继续安装 |
| A1-08 | P1 | latest 延迟超过 10 秒或断开连接，GitHub 可达；手动检查 | 服务器阶段约 10 秒内结束并回退 GitHub |
| A1-09 | P1 | 同时阻断服务器和 GitHub；手动检查 | 提示检查失败及原因；网页继续使用；自动检查失败无打扰 |
| A1-10 | P1 | 当前服务器 latest 已是最新，GitHub 存在更高版本；手动检查 | 以服务器结果为准，不回退 GitHub |
| A1-11 | P1 | 检查过程中切换服务器；或重建 WebView 后用旧页面凭据调用原始接口 | 旧服务器结果不展示；旧 WebView 与旧凭据调用被拒 |
