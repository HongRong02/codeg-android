# 开发流程（协调方）：规划 → 分层派发 → 到货 → 集成 → 测试 → 修复 → 发布

> 任务方只读 `CONVENTIONS.md`。具体命令见仓库根目录 `CLAUDE.md`。模板：`tasks/TEMPLATE.md`、`tests/TEMPLATE.md`、`bugs/TEMPLATE.md`。

## 分支模型
- `main`：只接收 `sit` 的整批合入和 `hotfix/*`。push main 即发版。
- `sit`：长期集成分支，CI 和真机测试都在这里做。除了解决合并冲突、重新生成 code-index、提交文档，不在 sit 上写业务代码。
- `task/Txx-<短名>`：开发任务，基于派发时的 sit。`fix/Bnn-<区域>`：修复任务，基于最新的 sit。
- `hotfix/<短名>`：基于 main，合入 main 发版后立刻把 main 合进 sit。
- **问题归属**：合入 sit **之前**发现的问题，在原 `task/*` 分支上修；合入 sit **之后**发现的问题，写 bug 单、开 `fix/*` 分支修，不回原分支。

## 1. 规划
- 每个批次一份关系图 `graphs/<批次>.md`（格式见文末），任务文档按模板写全头部：层级、硬依赖、软依赖、同层并行、冲突域。
- 派发前自检：
  - 同层之间没有硬依赖（有的话，把被依赖的一方上移一层）；
  - 同层冲突域不相交，共享追加点要在图里标出；
  - 软依赖写明契约（签名或文件名）和缺失时的占位做法；
  - 设计系统类任务定签名前，先扫描各页面的真实用法；
  - 同时运行的 Codex 不超过 8 个，超出时按关键路径优先。

## 2. 派发
- 主仓库先 checkout `sit`，有需要就先 `merge main`，然后推送。本层派完之前不要切换分支。
- 默认按层推进；某个节点的硬依赖都已 🔗 且 sit CI 是绿的，就可以提前派（就绪即派）。
- 在关系图里把节点改成 🔄，并记下 run ID。

## 3. 到货（逐个处理，不等同层其他任务）
- 读报告和测试文档；用 `git diff --name-only sit...origin/task/Txx` 和冲突域对比，越界就打回。
- 后台对该分支跑 verify。失败时，小问题我直接在原分支修，大问题把日志发回原任务。通过后改为 📦。

## 4. 集成
- 📦 的任务就用 `merge --no-ff` 合入 sit。一层全部合完后重新生成 code-index → 推送 → 跑 sit verify。
- **层级门禁**：sit CI 变绿，本层节点才能改为 🔗，下一层才能派。
- 合并时出现预期之外的冲突，说明规划有漏洞，记进关系图的"复盘"。

## 5. 测试
- 先把本批各测试文档合并成 `tests/PLAN-<批次>.md`（可以派给 Codex 做）：按页面组织，以最终状态为准去掉重复，分 P0（核心流程、危险确认、Toast，全部执行）/ P1（每页明暗截图对照网页端）/ P2（边界情况，抽样执行），末尾附"原用例 → 合并用例"覆盖对照表。
- 默认在批次末尾统一测，只装一次 APK；组件类用例在 debug 组件预览页上执行。按各测试文档逐条测，结果记到 `tests/RESULTS-<批次>.md`（用例 | ✅/❌/⚠️ | bug 单 | 截图）。

## 6. 修复
- 失败用例或 sit CI 失败 → 写 `bugs/Bnn-<区域>.md`。**同一区域一轮只开一个修复任务**，不同区域并行。
- 编译问题会阻塞所有测试，由我直接开 `fix/Bnn-build` 修。其他问题派 Codex 修，修复任务用 CI 模式。
- 修复分支合回 sit 后，复测对应用例和回归点，更新 RESULTS。循环到没有 ❌ 为止。

## 7. 发布
- 全量回归（标了"回归"的用例 + 明暗主题抽查）→ `main` 上 `merge --no-ff sit` → push → 在真机上验证自动更新。
- 关系图节点全部改为 ✅，补写复盘。

## 关系图格式
```
批次 <名称>：<目标>　状态：<进行中/已发布>
├─ L1 <层名>　[并行 ×N｜⟂]　门禁：<条件>
│  ├─ 组 A <组名>　⟂
│  │  └─ T01 <标题>　<状态>　← 硬：<任务>　⇠ 软：<任务>（契约：…）　冲突域：<文件/目录>
├─ L2 …
├─ SIT：编译门禁 → 真机测试 → 修复轮次
└─ 发布
```
- 状态：⏳ 待写文档　📝 文档就绪　🔄 开发中　📦 到货通过　🔗 已合入 sit　✅ 测试通过　❌ 有 bug（附 Bnn）
- `←` 硬依赖（需要对方代码已合入 sit，决定层级）；`⇠` 软依赖（只用对方的接口约定，可以同层）；`⟂` 互不依赖。
- 关系图是唯一事实来源，每一步都要同步更新状态。
