# T61 合并 UI1 测试计划

> 先读 `.taskmaster/docs/CONVENTIONS.md`。本任务只写文档，不改代码。

| 字段 | 值 |
|---|---|
| 批次 / 层级 | UI1 / SIT 准备 |
| 硬依赖 ← | T47–T60 的测试文档（都在 sit 上） |
| 冲突域 | 新建 `.taskmaster/docs/tests/PLAN-UI1.md`，只此一个文件 |
| 分支 / 基准 | `task/T61-test-plan` / 派发时的 `sit` |
| 测试方式 | 无（纯文档） |

## 目标
`.taskmaster/docs/tests/` 下 T47–T60 的 14 份测试文档共约 418 条用例，大量重叠：T47/T55、T48/T56、T49/T57、T50/T58 是同一批页面的第二、三阶段，第二阶段的中间状态已经被第三阶段取代；很多用例只是明/暗各写一遍。合并成一份可以在一台手机上高效执行的计划，**覆盖不能丢**。

## 需求
1. 读全部 14 份测试文档的用例、回归点和"已知风险"小节（不要读代码）。
2. 按**页面/入口**重新组织（例如：会话列表、会话详情、项目列表、Git 面板、设置首页、代理详情……、组件预览页的每个分组）。同一页面上测同一行为的用例合并成一条，以最终状态（第三阶段）为准。
3. 每条合并用例的格式：`编号(P-xx) | 优先级 | 入口 | 步骤 | 预期 | 主题 | 来源用例编号列表`。明/暗只在视觉检查时区分：功能用例默认只测一种主题，另起一条"明暗视觉"用例，统一切换主题截图。
4. 优先级：
   - **P0**：核心业务流程（发消息、权限/问题卡片、git 提交/推送等）、所有危险操作的二次确认（必须显示目标）、所有 Toast 触发、自动更新入口、release 版无法进入组件预览页。
   - **P1**：每个页面明/暗各一张截图，对照网页端对应页面（写明对照的 WEB 组件路径）。
   - **P2**：边界情况（超长文字、RTL、横屏、大字号、空列表、断网）。
5. 文档开头写：前置条件（测试服 T13Test、需要预先准备的数据）、执行顺序建议（按页面路径排列，尽量少来回跳转）、各优先级的用例数量。
6. 结尾附**覆盖对照表**：原用例编号 → 合并后编号；原文档里每一条都必须出现在这张表里（被判定为过时的写"由 P-xx 取代"并注明原因）。

## 验收
- `PLAN-UI1.md` 的覆盖对照表包含全部原始用例编号（提交前用 grep 自查数量，写在报告里）。
- 推送 `task/T61-test-plan`。不要触发 CI。
